# 微信档口助手正反向手测清单

版本：2026-09-18  
范围：商家微信 Bot 的 Excel 导入、产品图找货/上新、商品查询、商家正式报价单、档口资料，以及共用的审批链路。  
测试数据：只在测试档口使用；所有型号、成本和图片均为虚构数据。

## 0. 测试材料和通过口径

材料目录：`audit/round21/wechat-manual-kit/`

- `微信正向-吹风机.xlsx`：1 个 Sheet，Sheet 名是“微信验收吹风机”；4 行商品、4 张图。
- `微信并发-配件.xlsx`：第 2 个独立导入工单。
- `WX-HD15-red.jpg`：与导入表完全相同的已知商品图。
- `WX-unknown-green.jpg`：未入库的新图，用于上新。
- `反向-损坏Excel.xlsx`、`反向-伪装图片.png`：反向输入。

主表审批后必须满足：分类=微信验收吹风机；商品记录=4；型号依次含 `WX-HD15`、`WX-HD15`、`WX-HD16`、空型号。两个 `WX-HD15` 不得合并，空型号不得补造或丢弃，成本列不得向 TG 客户展示。

每个写操作都按以下通用口径验收：

1. 微信助手先说“已提交/待审批”，不能说“已经生效”。
2. 审批前查库，原数据不变。
3. 驳回后不变；批准后才变化。
4. 同一审批链接重复提交不能重复写入。
5. 两个工单修改同一份数据时，旧工单不能覆盖较新的状态。

| W-02 | `你能做什么？` | Excel 说明为“每个可见 Sheet 是一个分类，表头是规格”；写操作需审批 | 宣称发文件后直接入库 |
| W-03 | `要报价单` | 追问商品、数量和价格口径；未收齐前不生成文件 | 未选商品和数量就声称已出表 |
| W-04 | `WX-HD15 有几件库存？` | 明确“款数/商品记录不等于库存件数”；没有库存字段时不猜 | 把 2 条型号记录回答成“库存 2 件” |

## 2. Excel 导入

### 2.1 正向主链路

1. 把 `微信正向-吹风机.xlsx` 作为文件发给微信 Bot。
2. Bot 必须直接按 Sheet 名和表头创建动态分类导入，不需要商家先增加分类，也不得追问“剃须刀还是卷发棒”。出现这种追问即判失败，不要顺着旧流程回答。
3. 预期先收到“解析已启动”；解析完成后收到审批入口。
4. 在批准前发送：`微信验收吹风机有几个？` 预期没有新增 4 款。
5. 打开审批页，检查分类名、8 个表头字段、4 行和 4 张预览图；批准。
6. 再发送：`微信验收吹风机有几个？` 预期回答 4 款，且说明款数不是库存。
7. 发送：`微信验收吹风机都有哪些型号和颜色？` 预期实时查库；红/蓝两个 `WX-HD15` 分别存在，空型号行仍存在。
8. 在商品管理页确认 4 条记录默认客户可见；成本为内部字段。

### 2.2 驳回、并发和重复操作

| 编号 | 操作 | 预期结果 |
|---|---|---|
| E-01 | 发 `微信并发-配件.xlsx`，审批页选择驳回 | 不创建“微信验收配件”商品 |
| E-02 | 几乎同时重发同一主表两次，先批准一张，再批准另一张 | 第一张生效；第二张提示数据已变化/工单冲突，不得复制 4 行 |
| E-03 | 同一批准按钮连续点两次 | 第二次提示已处理或冲突；总数仍是 4 |
| E-04 | 主表改一行后重导，在审批前从 H5 修改同一商品，再批准旧导入 | 旧导入被拦截，不覆盖 H5 新值 |
| E-05 | 发 `反向-损坏Excel.xlsx` | 明确解析失败；不生成可批准的商品工单 |
| E-06 | 发 txt、PDF 或无有效表头的 Excel | 明确不支持/无法识别；不伪造导入成功 |
| E-07 | Excel 含一个隐藏 Sheet | 隐藏 Sheet 不创建分类 |
| E-08 | 重导时调换行顺序但内容不变 | 沿用原商品 ID，不把所有行当新增 |

## 3. 产品图找货和上新

### 3.1 已知图找货

1. 发 `WX-HD15-red.jpg`，再发：`帮我找库里相似商品。`
2. 预期返回 3 至 5 个候选，并明确“候选不等于已确认同款”；第一批应包含红色 `WX-HD15`。
3. 回复：`换一批。` 预期本次排除已展示商品 ID，不重复首批候选。
4. 回复：`第1个就是我要的。` 预期只确认选择，不自动改商品、不自动出报价单。

### 3.2 用图上新

1. 发 `WX-unknown-green.jpg`，并发送：`用这张图在微信验收吹风机新增商品，型号 WX-NEW-01，颜色绿色，功率 1400W，先设为不可观测。`
2. 预期生成新增审批工单；审批前查询 `WX-NEW-01` 不存在。
3. 打开审批页确认图片、分类、字段和“可观测=0”，批准。
4. 再查询应存在；客户 TG 查询时不展示该商品。
5. 通过 H5 改为可观测后，客户侧才可展示。

### 3.3 反向图片场景

| 编号 | 操作 | 预期结果 |
|---|---|---|
| P-01 | 只发一张新图，不说分类/型号 | 先追问必要资料，不静默建立空商品 |
| P-02 | 发 `反向-伪装图片.png`（若微信作为文件发送） | 报“图片损坏或不是有效图片”；不生成工单 |
| P-03 | 图片路径已被清理后再执行找货 | 报“图片不存在/请重发”，不返回伪候选 |
| P-04 | 新图向量分数低 | 仍只能称“相似候选”，不得断言同款 |
| P-05 | 新增时使用分类模板外字段 | 要求映射到已有字段或备注；不得凭空增加列 |
| P-06 | 上传空文件、超限图片、像素异常图片 | 拒绝并说明原因；暂存区不得留下可引用的假图片 |

## 5. 商家正式报价单

当前正式 ELETRO 报价模板只对已配置报价字段映射的旧版 `razor/curler` 分类开放。动态分类可能有多列成本/价格（本测试吹风机就有“成本”字段，真实表还可能有单风嘴、五风嘴等多列），系统不得猜选哪一列。

### 5.1 正向

1. 确认测试库中有批准状态的预置卷发棒，例如 `TEST-CURL-2026`，并已安装测试/商家报价模板。
2. 发送：`给 TEST-CURL-2026 出正式报价单，数量 81 个，价格调整 0%，定金 20%。`
3. 预期微信先确认识别到的商品和数量，再生成并推送 Excel 文件。
4. 下载后打开：文件可读；数量按箱规向上取整；单价、小计、总计、定金和尾款一致；有商品图时图片位于商品行；文件发送失败时任务留在发件箱重试，不能回“已送达”。

### 5.2 反向

| 编号 | 操作 | 预期结果 |
|---|---|---|
| B-01 | 只说 `出报价单` | 追问商品和数量，不生成空表 |
| B-02 | 数量传 0、负数、小数或文字无法确认 | 要求正整数，不生成文件 |
| B-03 | 商品不存在或已下架 | 拒绝生成，不拿相似商品代替 |
| B-04 | 定金小于 0 或大于 100；折扣造成调整比例小于 -100% | 拒绝参数，不生成文件 |
| B-05 | 对“微信验收吹风机”说 `直接出正式报价单` | 明确尚未配置动态分类的报价字段映射，不能猜成本列；不得假成功 |
| B-06 | 生成后模拟微信文件接口返回 500 | 文件任务保留并重试；不得标记已发送 |

## 6. 档口名称和联系方式

### 6.1 正向和审批语义

1. 发送：`档口名称改为微信验收档口，档口号 A-018，联系人测试老板，老板 TG 是 @wx_test_owner，微信是 WX-TEST-OWNER。`
2. 预期生成资料审批；随后问 `当前档口名称是什么？`，批准前仍是旧值。
3. 第一次驳回，确认所有字段不变。
4. 再提交同样资料并批准；随后查询应返回新值。
5. 从客户 TG 发送 `找老板`，预期同时返回已批准的 TG 和微信；不进入或转接原微信会话。

### 6.2 反向和冲突

| 编号 | 操作 | 预期结果 |
|---|---|---|
| C-01 | `档口名称改成空白` | 拒绝，原名称保留 |
| C-02 | `老板TG是 invalid/url` | 提示 Username 格式错误，不建有效工单 |
| C-03 | 微信号含换行或超过 100 字符 | 拒绝，原值保留 |
| C-04 | 同时提交“名称=甲”和“名称=乙”，先批准甲再批准乙 | 乙提示资料已变化/冲突，不能覆盖 |
| C-05 | 用过期或错误审批 token | 401/403/409，不修改资料 |
| C-06 | 尝试手填 TG Bot 数字 ID/Username（微信托管模式） | 提示必须走 Bot Token 专用绑定入口 |
| C-07 | `清空老板微信，只保留 TG` | 建立可审核的清空工单；批准后找老板只返回 TG |

## 8. 最终通过条件

- 所有正向用例都落到真实文件、数据库或审批状态，不只返回一段成功话术。
- 所有反向用例都在写库前失败；没有空工单、重复商品、假图片或假报价文件。
- Excel、图片、商品、档口资料的写操作均满足“审批前不变，批准后生效”。
- 商家微信能看内部资料；客户 TG 只看批准且可观测的公开规格和图片，不显示成本、价格、供应商链接或全商品页链接。
- “款数”始终解释为商品记录数；库存、交期、是否能发货只依据商家明确填写的资料。
- 正式报价文件生成和微信文件实际到达分别判定，不能把“已生成”说成“已送达”。
