# 测试档口全链路验收流程

## 测试档口

- 名称：全链路测试档口（非真实交易）
- 档口 ID：`caa0d647d631a356e7f5be33`
- 切换前缀：`caa0d647`
- 数据范围：独立数据库、独立图片目录、独立服务凭据，不读写正式档口商品
- 初始商品：`TEST-RZ-8226`、`TEST-CURL-2026`
- 所有商品和价格均为测试数据，不构成真实报价

商家从已授权的微信 Bot 进入测试档口商品管理页；`@kehu_serve_bot` 是本次商家创建并绑定的客户 Bot，只用于客户咨询、采购笔记和出表，不再承担档口认领、切换或商品管理。

## 完整验收顺序

### 1. 账号和档口隔离

1. 从已登记的商家微信进入商品管理页，确认页面显示“全链路测试档口（非真实交易）”。
2. 用未登记微信尝试调用商家写工具，应被拒绝。
3. 确认 H5、商家 API 和客户 Bot 返回相同的 `shop_id`。
4. 正式档口的商品数量和内容应保持不变。

### 2. 商品管理页面

1. 发送 `商品管理` 并打开链接。
2. 页面应显示两个初始测试商品及所属测试档口。
3. 新增 `TEST-MANUAL-TEMP`，修改一次颜色，再下架。
4. 客户可见商品中应出现新增商品；下架后应消失。

### 3. 两份 Excel 同时导入和独立审批

1. 同时提交 `concurrent-import-A.xlsx` 和 `concurrent-import-B.xlsx`。
2. 两份文件应各自进入解析，各生成一个待审批工单，不能相互覆盖。
3. 批准 A、拒绝 B。
4. A 中的两件商品应写入测试档口；B 中的商品不得写入。
5. 工单令牌只能使用一次，已决定的工单不能再次审批。

### 4. 客户实拍图询价

1. 客户依次发送四张实拍样品图。
2. Bot 应识别为五条采购项目，并逐条回显可修改字段。
3. 发送 `1 颜色改成黑色`，再发送 `第1条起订量一箱起`。
4. 发送 `确认`，五条项目应全部进入已确认状态。
5. 发送 `出表`，收到的 Excel 应有一行表头、五行商品和五张嵌入图片，且修改后的颜色、起订量正确。
6. 用档口某件可观测商品的原图发送一次，应返回该商品候选；客户仍需回复 `询价1` 确认。
7. 发送与档口商品无关的图片，不得为了凑结果返回低相似度商品；图片仍应正常整理进采购清单。

### 5. 商品查询、商家报价原文和转人工

依次检查：

| 客户消息 | 预期结果 |
| --- | --- |
| `看看商品` | 只返回当前档口中客户可见的商品 |
| `TEST-RZ-8226 100个多少钱` | 不展示商品价格；只按商家已审批红线决定是否转人工，未命中且资料不足时明确不能确认 |
| `可以月结60天吗？` | 命中商家已配置的账期红线并给出人工联系方式 |
| `可以月结15天吗？` | 未达到商家配置条件，不应误转人工 |
| `找老板` | 返回商家 Telegram 和微信联系方式 |

新档口初始没有业务转人工红线。价格、物流、定制、账期、售后等示例只用于引导商家填写；商家没有通过微信 Bot 建立并审批的条件，不会触发转人工。客户主动回复“找老板”时仍直接提供已登记的联系方式。

### 6. 商家自己的客户 Bot

测试档口需要由档口老板提供一枚没有被其他服务占用的 Telegram Bot Token，系统将它一对一绑定给该档口。门店把该 Bot 的 `t.me` 链接或二维码提供给客户扫码，才可进行 Telegram 网络层的最终验收。绑定后检查：

1. 商家 Bot `/start` 能返回测试档口欢迎语。
2. 客户发图、修改、确认、出表均在该 Bot 内完成。
3. 红线问题转人工时返回测试档口配置的微信和 Telegram。
4. 两个客户账号的数据和清单互不可见。
5. 停用商家 Bot 后轮询进程退出，商品管理 API 仍按档口状态受控。

商家配置入口是微信 Bot 和 H5；Telegram 只保留商家自己创建并绑定的客户 Bot。客户 Bot 不提供档口认领、Token 绑定或商家管理命令。

## 自动验收

服务器执行：

```bash
cd /home/ubuntu/dangkou-v2
set -a; . ./.env.merchant-hub; set +a
.venv-unified/bin/python scripts/run_test_shop_acceptance.py \
  --merchant-id caa0d647d631a356e7f5be33 \
  --photos-dir /home/ubuntu/dangkou-test-samples \
  --out /home/ubuntu/dangkou-test-shop-20260918/acceptance-latest \
  --with-imports
```

脚本覆盖服务健康检查、商品增改下架、双导入审批、四张真实图片、字段修改、确认、带图 Excel、商品查询、报价原文、红线条件和人工联系方式。重复执行时会复用已经完成的双导入验收结果，不会再次写入同一批测试商品。
