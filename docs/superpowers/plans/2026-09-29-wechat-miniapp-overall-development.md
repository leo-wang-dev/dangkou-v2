# 微信小程序与全局采购助手开发方案

日期：2026-09-29。定位：一套中央采购身份与跨档口笔记服务，多个独立档口商品/客服服务，uni-app 同源代码构建 H5 与微信小程序。微信登录是小程序的便捷登录方式；游客仍可用，邮箱验证码保留为跨端与找回方式。

## 已接入的身份流程

1. 采购员可先以游客拍照记笔记或进入某档口客服。微信小程序点击「微信登录」时，`uni.login` 取得一次性 code，提交中央 `/tool/auth/wechat`。AppSecret 只在中央服务，中央向微信换取 openid 后签发自己的 bearer；客户端从不持有 openid、session_key 或 AppSecret。
2. 中央工具的有效游客笔记和名片批次在登录事务中转入微信账号，原游客令牌立即失效。档口客服另外以已签发的中央 bearer 调用本店 claim 接口，将本店游客聊天、清单与照片转入同一个稳定 `account_id`。不同档口仍各自存放数据；中央清单按档口名片分组导出。
3. 已有邮箱登录者点击「绑定微信」后，微信身份直接关联当前中央账号。微信用户点击「绑定邮箱」时必须完成邮箱验证码，中央笔记并入已存在的邮箱账号。绑定冲突返回 409，不自动覆盖另一人的绑定。后续微信重复登录恢复同一账号。
4. 退出当前设备撤销中央会话，保留账号数据；游客未登录期间的数据只依照游客会话规则保存。H5 继续使用邮箱登录，微信小程序同时提供微信和邮箱入口。

## 系统边界与路由

- 中央服务：微信换码、邮箱验证码、账号会话、全局采购笔记/名片/多档口 Excel；独立 SQLite 与进程。
- 档口服务：模板审批、商品库、报价、商品搜索、客服会话、单店清单；每档口独立运行时和数据库。档口仅向中央 `/me` 验证 bearer，使用服务端取得的 `account_id`，不信任客户端传入邮箱。
- uni-app：采购工具页、档口客服页、清单页。客服入口通过档口 `mid` 路由；小程序版以业务域名调用中央和对应档口网关，不在包内保存密钥。H5 和小程序共用数据契约及 13 种语言资源。
- 微信商家 Bot：用于商家导入/审批/通知，与采购员微信小程序登录是两条身份链，不互相充当登录凭据。

## 分阶段交付

1. **A 身份接入（本次）**：交付中央微信换码与绑定、游客合并、小程序两页入口、冲突处理。以后端 HTTP 测试覆盖重复登录、绑定、错误凭证和游客迁移，并通过 H5 与小程序编译。
2. **B 微信联调与发布**：配置 AppID、服务端 AppSecret、备案 HTTPS 域名和微信后台 request/upload/download 合法域名。体验版真机完成扫码、登录、重开、换设备、邮箱绑定和拍照请求。当前 IP 地址不能代替正式合法域名。
3. **C 跨店账号合并补强**：当邮箱和微信账号在某档口都已有历史时，迁移旧 `account_id` 的清单与聊天。两个独立档口分别验证无丢失、无重复。当前中央笔记已合并，店铺历史的双账号合并仍需此阶段。
4. **D 客户演示闭环**：真 Excel 导入、模板审批、商品图/价格、拍照搜索、名片分组导出、客服多语言和报价通知逐条重跑 TC1–TC16。每项留公开 API 响应、浏览器/真机操作、导出文件和通知结果，人工环节单独记录。
5. **E 正式运营**：邮件投递、监控、备份、限流、故障恢复与客户隔离部署。生产不记录验证码明文；备份可恢复；中央不可用时档口账号请求明确失败，不能降级成游客。

## 发布前必须具备的配置

1. 在微信小程序后台取得 AppID，并在服务端安全注入 `WECHAT_MINIAPP_APP_ID`、`WECHAT_MINIAPP_APP_SECRET`；AppSecret 不写仓库、文档、前端构建物或聊天消息。`frontend/src/manifest.json` 的 `mp-weixin.appid` 需由发布构建填入 AppID。
2. 准备微信允许的 HTTPS 业务域名与有效证书，并加入小程序合法域名列表。当前 `https://134.175.135.102:80` 只是隔离测试机地址，不能作为正式小程序网络配置。
3. 中央和每个档口分别配置域名/网关路由，确认客服 `mid` 映射到正确独立运行时；中央 bearer 校验只走服务端私有地址。
4. 体验版通过后再发布正式版；开发版允许的域名校验例外不视为正式验收。

## 风险与验证矩阵

- 身份冲突：同一 openid 已绑定其他邮箱必须拒绝；邮箱验证码验证失败不得改变绑定。
- 数据迁移：中央游客迁移与微信映射在同一事务；档口 claim 失败保留原游客凭据并可重试。阶段 C 前不承诺两个既有档口账号的历史自动合并。
- 数据隔离：每个 bearer 只能读自己的中央清单和本店记录；每个客服链接只能进入对应档口。
- 外部依赖：无 AppID/AppSecret 时 `/auth/wechat` 返回 503；真实微信换码、真机授权和正式域名验证必须在配置完成后重跑，不能用 mock 测试代替。
- 回归：后端全量 pytest、前端行为测试、H5/MP 构建、隔离服务器公开接口请求、真机页面点击；每次改动后复测受影响场景。
