# Customer language contract

Canonical codes are `zh/en/fr/es/pt/ru/ar/de/ja/ko/vi/th/id`. `中文` and `English` remain accepted legacy inputs and normalize to `zh` and `en`. The canonical fixed resource is `frontend/src/customer-languages.json`; `scripts/build_customer_languages.py` regenerates module/classic-browser assets. `customer-source-aliases.json` maps historical display spellings without changing stored field keys.

Customer clients send `X-Customer-Language`; download links can use `?lang=ar`. The selected UI preference is `dk_lang`, independent of transient guest credentials. Shop `/lang` persists the canonical preference in `cs_customer`; text turns apply an explicit request preference inside snapshot/replay, so they do not take a writer before model work. Without an explicit request preference, replay reads the latest stored language. Central `/lang` stores the guest/account preference, current central guest preference follows the verified merge, and `/me` returns the persisted account language for another device.

Chat buttons send machine actions (`contact_owner`, `export`, `confirm`). Photo modes and batch actions retain the Task4 machine codes. Fixed UI, errors, photo receipts, standard note headers and quotation labels use local resources. Notes retain extracted evidence and original field keys; reserved missing/unclear markers are localized for display. Editable cells do not write a localized placeholder merely on focus/blur.

Dynamic chat translation runs inside Task1 planning/cache replay. Every provider batch finishes before translation cache writes. Identifiers, supplied model/supplier identities, phone numbers, amounts, email addresses and URLs are masked per occurrence and validated before restoration/cache reuse. A corrupt, unchanged or unavailable translation displays a localized `translationUnavailable` notice with the original text. Freeform note values remain original evidence. Live translation quality and native-language review are separate from offline behavior verification.

Quotation API/plugin accepts optional `target_language`, default `zh`. The admin stays Chinese and offers a per-product quantity/language action, using the existing quote calculation and supplier identity. Quotation labels, totals and carton-adjustment footer follow the target language; numeric cells retain Decimal results and numeric types. Description/color translation may use the provider before notification/outbox writes; callers already in a write transaction get an explicit untranslated fallback. API results additionally include the canonical `target_language` and authenticated `download_url`; `/quotes/quote-<8 hex>.xlsx` uses the existing service authentication. Merchant notifications and plugin administrative explanations stay Chinese.

Arabic pages use RTL layout; worksheets set `rightToLeft`, and raw model/data cells retain LTR reading order. Under `/tool/`, customer-service fetch/upload/export routes resolve at `/cs/...`; browser photo sources resolve to full URLs because uni-app otherwise rewrites root-relative image paths below its public path. Tool requests keep their own deployment prefix. Both H5 and Weixin builds are retained; formal mini-program release remains deferred.

The unanswered central-plus-shop authenticated history choice is unchanged and remains pending. This task does not establish shop account login, cross-database identity, history discovery or migration.
