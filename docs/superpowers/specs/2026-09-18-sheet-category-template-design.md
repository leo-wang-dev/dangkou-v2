# Sheet 分类模板设计

## 目标

商家上传 Excel 后，每个有效 Sheet 代表一个商品分类，Sheet 中识别出的表头定义该分类的规格字段。首次导入在一张审批页中同时确认分类模板和商品；后续结构相近的 Sheet 复用或升级原模板。

## 已确认规则

- 分类名称默认取 Sheet 名；标题行只保存为说明，商家可在审批时改名。
- 表头不要求位于物理第一行，由解析器识别。一个工作簿可包含多个 Sheet，每个有效 Sheet 独立形成分类。
- 每个数据行是一条独立商品，不因型号相同而合并。型号可以为空且保持为空，系统生成内部 ID，绝不编造商家型号。
- 图片按所在数据行归属；同一行多张图片全部保留，第一张为主图。
- 首次审批同时展示模板字段及商品行；批准后模板与商品一起生效。
- 字段保存原始文本。复合装箱、体积、重量不强拆；未来可以增加辅助结构，但不能覆盖原文。
- AI 推断字段类型、公开范围和搜索属性，商家在审批页确认。包含“成本”的字段默认内部可见；型号、颜色、图片和包装规格默认公开。
- 相似表头只产生“复用模板/升级模板/新建分类”的候选，不能静默归类。模板升级使用版本号，旧数据不丢失。
- 再次导入按来源、Sheet、行指纹、图片指纹和已确认映射比较；不能确定的匹配进入审批，缺失旧行只生成疑似下架项。
- 动态分类按档口隔离。现有剃须刀、卷发棒作为预置模板继续兼容，并逐步走同一套读取接口。
- 商家可下载标准空白模板：分类标题、确认后的表头、示例行；不复制原文件复杂合并格式。

## 数据模型

`category_template` 保存当前分类定义：稳定 key、名称、版本、字段 JSON、状态和来源 Sheet。字段包含 `key`、`label`、`type`、`required`、`visibility`、`searchable`、`role` 和顺序。

`category_template_version` 保存每次批准的不可变模板快照。

`product_dynamic` 保存动态分类商品：内部 ID、分类 key、原始字段 JSON、图片、来源信息、行指纹、状态和客户可见开关。空型号不影响落库。

现有两个物理商品表暂时保留，通过统一目录读取层与动态商品一起提供给商家 H5、客户展示和 TG 查询，避免一次迁移破坏现有数据。

## 导入与审批

上传时允许不传分类。系统读取所有可见 Sheet，识别标题行、表头行、字段定义、数据行和图片锚点，生成导入草稿。若命中现有模板则给出匹配依据；否则附带新模板草稿。

审批页先显示分类模板，再显示逐行商品。模板与商品必须在同一事务内批准；模板审批失败时不写入商品。后续导入继续使用新增、更新、疑似下架三类审批结果。

## 对客边界

TG 查询商品时不返回商品展示页或全量目录链接。Bot 只在聊天中介绍少量已批准、客户可见商品的公开规格，并发送少量商品图；价格、成本、内部备注和系统 ID 一律不返回。商家 H5 可以展示完整管理信息。商品图片每次发送前重新校验商品可见性。
