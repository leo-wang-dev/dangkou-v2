## 1. 背景与重构理由

### 1.1 v1 做了什么

v1 版本建立了一套**通用商品字段体系**：不论什么品类，所有商品用同一套 30 个字段（品名/货号/颜色/尺寸/装箱数/价格……）描述，配一套 AI 解析引擎，把商家发来的 Excel/PDF/PPT 资料解析进这套统一字段，再提供图片检索找货。

### 1.2 实测暴露的核心矛盾：通用字段 ≠ 商户的真实字段

近期用真实商户资料做全链路实测（剃须刀现货表、卷发棒（华岳电器）目录、科森报价单），暴露出根本性矛盾：

- **每个品类的"重要字段"完全不同**。剃须刀商户关心功能描述、彩盒尺寸、单套重量；卷发棒商户关心电压、功率、发热体、材质；而发给客户看的报价单只有 5 列（型号/图片/价格/规格/起订量）。通用 30 字段在这三张真实表面前，要么大面积空置，要么硬凑错位——**商户打开系统看到的不是自己熟悉的货**。
- **解析质量失去锚点**。通用字段要求 AI 把任何格式"翻译"进固定框架，字段对不上时 AI 只能编造或留空，实测出现过整批商品字段串位、行数当商品数、图片张冠李戴等问题。字段越贴近商家原表，解析准确率越有硬性验收标准。
- **报价环节断链**。商户最终要发的是"自己那张样子的报价单"，通用字段导出的表客户不认。

### 1.3 新方向：品类模板制

字段体系反转——**商家品类模板定义系统字段**：

- 每个品类一套模板，字段直接取自商户真实在用的 Excel 表头，人工确认后固化；
- 商户在系统里看到的商品页 = 自己那张表的列，零学习成本；
- AI 解析有了确定目标（模板字段固定），准确率可验收；
- 检索确认后可直接按报价单模板出 Excel 发给客户，询价-报价形成闭环。

### 1.4 为什么整体重构而不是在 v1 上改

- **三层核心结构全部更换，没有可保留的"层内改造"路径**：
  1. **建表结构**：从通用单一大表（31 固定字段）换成品类物理表（剃须刀、卷发棒各一张，列即模板字段），主键/去重键/索引语义全部重建；
  2. **检索机制**：检索池按品类组织，候选结果的展示绑定该品类模板字段（卷发棒报电压功率、剃须刀报彩盒重量），通用检索的展示层无法复用；
  3. **管理页面**：从通用表格页换成"审核页 + 品类页签 + 模板字段增删改查"的新交互结构，页面几乎全新开发。
- **新增报价单能力是全新模块**：v1 没有任何对外文件输出，本次新增模板化报价单生成 + 微信发文件链路，属增量新建而非改造。
- 曾评估过"自动化模板导入"（从任意 Excel 自动生成品类模板），论证后放弃：真实需求是适配具体商家，不是通用 SaaS（详见决策记录 #3）。
- **v1 属内部验证性质**。其数据全部为测试数据，无生产迁移价值；保留旧结构反而让系统长期背着"通用字段"的包袱。
- **重写不等于从零**。v1 实战验证过的零件直接复用：微信接入与消息链路、AI Agent 异步解析引擎与提示词方法论（同型号合并/变体归并/图片配对等硬约束）、审批工单机制（一切写操作必经人工审批）、图片向量检索底座。**重写的是字段、检索组织与页面层，复用的是管道与安全层。**

### 1.5 重构价值（给业务的承诺）

1. **商户零学习成本**：系统里的商品页就是他自己那张表的线上版。
2. **解析准确率可承诺**：字段固定+自动验收标准（空型号=0、图片配对≥95% 等），不再靠感觉。
3. **询价-报价闭环**：客户拿图来问 → 秒出候选 → 一句话生成可发客户的报价单。
4. **品类扩展路径清晰**：新增品类 = 确认一套新模板 + 新增一张表，不动系统骨架。

## 2. 本期范围

- 输入格式：**仅 Excel**（PDF/PPT 解析成本高——尤其图片型 PDF——后续迭代再上）
- 品类：**剃须刀、卷发棒** 两个（当前真实在售品类），单级分类
- 不做：任意模板生成功能、动态新增品类、多级分类（见 §8 非目标）

## 3. 模板定义（从真实文件固化，人工已确认）

### 3.1 品类模板 A：剃须刀（源：剃须刀现货.xls，32 行/50 图）

| 字段 | 说明 |
|---|---|
| 序号 | 仅排序展示 |
| 产品型号 ★ | 货号/去重键 |
| 产品图片 | 一货一图 |
| 功能描述 / 颜色 / 产品尺寸(mm) / 彩盒尺寸(mm) / 单套重量(g) / 箱规 / 报价(不含税不含运) | 规格字段 |
| **内部货号** | 系统生成 `KS-XXXXXXXX`（去混淆字符集），商家内部管理用，不对外 |

### 3.2 品类模板 B：卷发棒（源：华岳电器有限公司.xlsx，65 行/65 图）

| 字段 | 说明 |
|---|---|
| ITEM.NO 型号 ★ | 货号/去重键（如 8225/8226） |
| 产品图片 | 一货一图 |
| 装箱尺寸 / 装箱数量 / 价格 / 电压 / 功率 / 发热体 / 材质 / 频率 | 规格字段 |
| **内部货号** | 同上 |

★ 同型号多行合并为一条商品（颜色/规格变体用 `/` 连接）；**同一型号绝不允许出现两条**。

### 3.3 报价单模板（源：科森报价表20260724.xlsx）

`型号 | 图片（嵌入缩略图）| 价格 | 产品规格（尺寸/颜色拼串）| 起订量`

极简 5 列，输出即可直接转发客户。起订量映射：卷发棒=装箱数量；剃须刀无此字段，若箱规文本含数量则取之，否则留空。

## 4. 产品流程

### 4.1 导入（异步 + 回调 + 审批）

```
商家微信发 Excel → AI 反问品类（"剃须刀 / 卷发棒"，能从文件预判则带建议）
→ 异步解析（AI Agent 按该品类模板字段抽取，硬约束：同型号唯一/变体归并/
  一货一图/原文有就填没有留空/定稿自检）
→ 解析完成：微信回调推送 + 审批页链接
→ 整批审批单（新增 N / 更新 M / 下架 K，逐行可改可毙）
→ 审批通过：入库 + 图片落位 + 进入检索池
```

### 4.2 重复导入的四分类语义

同一商家后续再发 Excel：**新文件/加行 = 新增；删行 = 下架；改值 = 更新**。匹配键 = 品类 + 型号。全部经审批落库。

### 4.3 商品管理（H5）

- 第一屏 = 审核页（待办工单）；第二屏 = 商品页
- 顶部品类页签（剃须刀 | 卷发棒）→ 表格列 = 该品类模板字段 → 行内编辑 / 新增 / 软删（下架）
- 图片：大图查看、更换主图、补传
- **AI 代操作**：微信对话里说"把 8226 价格改成 23"→ 生成修改审批单（改前/改后对照）→ 审批页批准生效。一切写操作必经人工审批，AI 不直接落库。

### 4.4 图片检索

```
微信发客户图 → 图片向量匹配 → Top3-5 候选：
"最可能：KS-0007｜8226 卷发棒｜42W｜￥21.5"…
→ 回复 1/2/3 确认 · 换一批（排除已展示重新推荐）· 发报价单
```
上线前用已入库商品图自动测评检索质量（Top1 ≥80% / Top3 ≥95%）；不达标时启用备选优化路线：文本向量融合 → 大模型精排。

### 4.5 报价单导出

检索确认后回复**"没问题"或"发报价单"** → 按报价单模板生成 Excel → 微信发文件 → 商家直接转发客户。

## 5. 技术架构

```
微信 ⇄ 消息引擎（复用现有平台，微信接入已验证）
        └─ AI 主对话 + 商品插件（工具层定义解析 Sub Agent、异步导入、回调推送）
              ↓ HTTP + 服务令牌
        商品服务（全新 FastAPI + SQLite）
```

```sql
product_razor:  id | 内部货号(唯一) | 产品型号 | 功能描述 | 颜色 | 产品尺寸mm | 彩盒尺寸mm |
                单套重量g | 箱规 | 报价 | 状态 | 图片 | 时间戳
product_curler: id | 内部货号 | ITEM.NO | 装箱尺寸 | 装箱数量 | 价格 | 电压 | 功率 |
                发热体 | 材质 | 频率 | 状态 | 图片 | 时间戳
embedding:      商品id | 品类 | 图片路径 | 图向量(1024维) | 文本向量(预留优化位)
approval_ticket: 审批工单（一次性令牌链接）
import_doc:     导入批次（文件、品类、状态、统计）
```

- 模板定义固化在代码常量（本期模板固定，不建模板表）
- 图片存储做**接口抽象**：本期存服务器本地（带鉴权出图），预留对象存储实现——届时使用**专用新 Bucket + 独立访问凭证**，与公司其他项目的存储完全隔离，仅改配置即可切换
- 解析引擎：AI Agent（Claude Code，sonnet-5 起步，网关可配置可替换；解析提示词沿用实测形成的硬约束方法论）

## 6. 自动化验收标准

| 场景 | 验收点 |
|---|---|
| 导入×2 | 两品类各导一次：品类询问→异步→回调→工单；审批后商品数正确（剃须刀约 25-35 / 卷发棒约 55-65）、空型号=0、图片配对≥95%、无虚构图片名 |
| 重复导入 | 改行/删行/加行再导：新增/更新/下架分别正确进审批 |
| 商品管理 | 按品类增/改/软删全通；AI 修改走审批生效 |
| 检索质量 | Top1 ≥80% / Top3 ≥95%（自动测评） |
| 报价单 | 5 列齐、图片嵌入、文件可正常打开 |
| 端到端 | 人工全流程走通：发文件→答品类→收回调→批工单→发图找货→发报价单→收 Excel |

## 8. 非目标（本期不做，后续迭代）

- PDF / PPT 解析（图片型 PDF 成本高，主链路先行）
- 任意模板动态生成 / 商户自助建模板
- 动态新增品类（加品类需人工确认模板 + 发版）
- 多级商品分类
- 微信快捷按钮（平台不支持）

## 9. 关键决策记录（评审时已逐项论证）

| # | 决策 | 结论 | 论证要点 |
|---|---|---|---|
| 1 | 输入格式 | 仅 Excel 先行 | PDF/PPT 尤其图片型解析需增加 2-3 天以上，先跑通业务主链路 |
| 2 | 品类选择 | 剃须刀 + 卷发棒 | 商户当前真实在售的两个品类，资料齐全可即时验收 |
| 3 | 模板形态 | 人工确认后固化，不做自动化模板导入 | 曾立项评估"任意 Excel 自动生成模板"，论证后放弃：真实需求是适配具体商家而非通用 SaaS，动态模板生成属过度设计 |
| 4 | 存储结构 | 品类物理表 | 模板固定品类少，"列即模板"使页面/查询/导出零翻译层；单表 JSON 方案为动态品类留的灵活性本期用不上 |
| 5 | 写操作安全 | 一切落库必经人工审批（导入/AI 操作均不例外） | 数据是商户资产，AI 只产审批单不直接写库 |
| 6 | 图片存储 | 本期服务器本地 + 接口抽象，后续切对象存储专用桶 | 不与公司其他项目存储混用；专用 Bucket + 独立凭证实现账号级隔离，切换仅改配置 |
| 7 | 检索方案 | 图向量匹配（沿用已验证方案）+ 质量门槛 | 上线前自动测评 Top1≥80%/Top3≥95%；预留文本向量融合与大模型精排两条优化路线 |
| 8 | 报价单触发 | 用户回复"没问题/发报价单" | 微信无快捷按钮；多数检索只需口头报价，按需出文件避免刷屏 |
| 9 | 起订量映射 | 卷发棒=装箱数量；剃须刀从箱规文本解析或留空 | 剃须刀模板原生无此字段，不编造 |
| 10 | 旧系统处置 | 全部废弃，不做数据迁移 | 旧数据均为测试数据；避免通用字段体系长期成为包袱 |
| 11 | 内部货号 | 沿用 KS-XXXXXXXX 生成规则 | 商户内部管理视角，与厂家型号并存 |

# 版本 v2.1 增补（2026-09-01 同事实测后迭代）

> **基线：v2.1 的所有变更基于 v2.0**（即本文上半部分的完整系统）。
> 上文提到的"v1"是指被 v2.0 重写替换的旧系统（通用31字段），与 v2.1 无关。

## 新增功能

### A. 商品统计查询（catalog_stats）

用户在微信直接问数据问题，AI 调 `catalog_stats` 工具查询：

| 用户说 | 系统返回 |
|---|---|
| "一共有多少款产品？" | 总数 + 按品类数量 |
| "卷发棒有多少个？" | 该品类数量 + 示例商品 |
| "剃须刀都有哪些型号？" | 品类数量 + 前3个示例 |

API：`GET /stats` → `{total, by_category, category_keys, samples}`

### B. 多商品灵活报价（catalog_quote v2）

| 项 | 说明 |
|---|---|
| 多商品 | 一次报价可选多个商品 |
| 各自数量 | 每个商品可设不同数量（如 A 款 100 台、B 款 500 台） |
| 百分比调整 | 正=上浮 / 负=下浮（如 +3% 加利润、-5% 给折扣、+3% 外贸佣金） |
| 实时计算 | 单价 = round(出厂价 × (1 ± pct%))；小计 = 单价 × 数量；合计 = Σ小计 |
| 模板 | 从源 Excel 模板（IN STOCK ITEMS Sheet）截取前 14 行公司抬头，**原样保留** |
| 新增列 | Qty（数量）、Amount（小计）加在 PRICE 后 |
| 合计行 | 自动生成 TOTAL 行 |

调用示例：
```
用户："HS09 第一款要100台，第二款要500台，出厂价加3个点"

AI 调 catalog_quote:
  items: [
    {product_id: "xxx", quantity: 100},
    {product_id: "yyy", quantity: 500}
  ]
  price_adjustment_pct: 3
```

### C. 数据模型不变

- 导入的 price = 出厂价（唯一存储价格）
- 销售价 = 报价时实时计算（不存库）
- 数量 = 报价时实时给（不存库）

### D. AI 操作增强

| 增强 | 说明 |
|---|---|
| 图片关联 | AI 新增/修改商品时可带用户发的图片（imagePaths 参数） |
| .bin 格式 | 微信图片自动检测真实格式（PNG/JPG/TIFF/BMP）并重命名 |
| 审批显示 | mutate 工单显示改前→改后对比卡片（不再 dump JSON） |

### E. H5 管理页增强

| 增强 | 说明 |
|---|---|
| 直写模式 | 商品页增/改/下架不走审批（用户本人=审批人） |
| 编辑持久化 | 审批明细编辑立即写回服务器，刷新可见 |
| 单行通过 | ✓ 按钮立即落库指定行（不用等整单） |
| 图片管理 | 编辑框内可删图/传图（与字段一起提交） |
| 多图支持 | 商品卡片 N 图角标 + 灯箱翻页 |
| 重复标黄 | 审批明细中重复型号 ⚠️ 标记 |

## 合并逻辑变更（v2.1 拍板）

- **去掉所有合并**：每一行数据 = 一个独立商品（宁可多进让人驳回，不能少进让人补）
- 提示词按品类独立（RAZOR_PROMPT / CURLER_PROMPT 各自维护，可单独微调）
- 重导四分类保留：同型号 → 更新；不在新文件 → 下架

## 品类模板独立提示词

每个品类有完整独立的提示词（`templates.py` 中 `prompt` 字段），互不影响：

```
RAZOR_PROMPT = "..."  ← 剃须刀专用
CURLER_PROMPT = "..." ← 卷发棒专用
```

后续品类解析不准时，只改该品类的 prompt 字符串。
