## 1. 改版要点（为什么重写）

- v1.1 的"30 字段优先级模板 + 品类专有列 + 三层字段体系"**整体废弃**：字段体系从"我们预定义"反转为"商家品类模板定义"。
- 本期**不做**"任意 Excel → 模板 Excel"的模板生成功能：模板从用户提供的真实文件**人工确认后固化**，写死在代码常量里。
- 旧系统与旧数据**全部废弃**，服务器清空，代码全新重写（旧仓库只读参考，可直接搬已验证实现）。

## 2. 本期范围

- 输入格式：**仅 Excel**（PDF/PPT 后续迭代）
- 品类：**剃须刀、卷发棒** 两个，单级分类
- 交付形态：一夜实现 + 自动化验收 Harness；次晨用户连微信跑全程

## 3. 模板定义（从源文件固化）

### 3.1 品类模板 A：剃须刀（源：剃须刀现货.xls，32 行/50 图）

| 字段 | 说明 |
|---|---|
| 序号 | 仅排序展示 |
| 产品型号 ★ | 货号/去重键 |
| 产品图片 | 内嵌图，一货一图 |
| 功能描述 / 颜色 / 产品尺寸(mm) / 彩盒尺寸(mm) / 单套重量(g) / 箱规 / 报价(不含税不含运) | 规格字段 |
| **内部货号** | 系统生成 `KS-XXXXXXXX`（去混淆字符集，沿 v1 规则），商家内部视角 |

### 3.2 品类模板 B：卷发棒（源：华岳电器有限公司.xlsx，65 行/65 图，散装双行表头）

| 字段 | 说明 |
|---|---|
| ITEM.NO 型号 ★ | 货号/去重键（如 8225/8226） |
| 产品图片 | B-F 无表头图片列，一货一图 |
| 装箱尺寸 / 装箱数量 / 价格 / 电压 / 功率 / 发热体 / 材质 / 频率 | 规格字段 |
| **内部货号** | 同上 |

★ 同型号多行合并为一条商品（颜色/规格变体用 `/` 连接），同型号绝不能出现两条。

### 3.3 报价单模板（源：科森报价表20260724.xlsx）

`型号 | 图片（嵌入缩略图）| 价格 | 产品规格（尺寸/颜色拼串）| 起订量（映射装箱数量）` —— 极简 5 列，商家可原样转发客户。

## 4. 四大产品流

### 4.1 导入（异步 + 回调 + 审批）

```
微信发 Excel → Agent 反问品类（"剃须刀 / 卷发棒"，文件名可猜则带建议）
→ 异步解析：claude -p（sonnet-5@ccdox 起步），提示词 = 硬约束纪律 + 该品类模板字段
   （同型号唯一 / 变体合并 / 一货一图 / 原文有就填没有留空 / 定稿自检）
→ 解析完成：微信回调推送 + H5 审批链接
→ 整批审批单（新增 N / 更新 M / 下架 K，逐行可改可毙）
→ 通过后：入库 + 图片落位 + 向量入池
```

### 4.2 重导四分类语义

同一商家后续再导 Excel：**新文件/加行 = 新增；删行 = 下架；改值 = 更新**。匹配键 = 品类 + 型号。全部经审批落库。

### 4.3 商品页 CRUD（H5）

- 第一屏 = 审核页（待办工单）；第二屏 = 商品页
- 顶部品类 tab（剃须刀 | 卷发棒）→ 表格列 = 该品类模板字段 → 行内编辑 / 新增表单 / 软删（下架）
- 图片：大图查看、换主图、补传
- Agent 增删改：微信对话触发 → 生成修改审批单（改前/改后对照）→ H5 批准生效。一切写操作必经审批。

### 4.4 图片检索（沿 v1 方案 + 强制自动测评）

```
找货会话发图 → qwen3-vl-embedding 1024维图向量 × 向量池余弦
→ Top3-5："最可能：KS-0007｜8226 卷发棒｜42W｜￥21.5"…
→ 回复 1/2/3 确认 · 换一批（排除已展示重取）· 发报价单
```
检索质量由 Harness 强制测评；不达标自动触发优化路线：`text_vec` 文本向量融合 → LLM rerank（embedding 表已预留列）。

### 4.5 报价单导出

检索确认后回复**"没问题"或"发报价单"** → 按科森模板生成 xlsx → 微信发文件。无快捷按钮（微信不支持）。

## 5. 技术架构（已选方案 A：品类物理表）

```
微信 ⇄ dsh-engine（保留，微信接入平台）
        └─ 主对话(DeepSeek) + catalog-v2 插件（工具定义含 Sub Agent、异步导入、回调推送）
              ↓ HTTP + 服务令牌
        侧车 catalog-v2（全新 FastAPI + SQLite，:8890）
```

```sql
product_razor:  id(uuid) | inner_code(唯一) | 产品型号 | 功能描述 | 颜色 | 产品尺寸mm |
                彩盒尺寸mm | 单套重量g | 箱规 | 报价 | status | 图片列 | 时间戳
product_curler: id | inner_code | ITEM.NO | 装箱尺寸 | 装箱数量 | 价格 | 电压 | 功率 |
                发热体 | 材质 | 频率 | status | 图片列 | 时间戳
embedding:      product_id | category | image_path | vec(1024) | text_vec(预留)
approval_ticket: 沿 v1 设计（一次性 token 链接）
import_doc:      导入批次（文件、品类、状态、统计）
```

- 模板定义 = 代码常量（不建表，YAGNI）
- **图片存储接口抽象 `local | oss`**：本期服务器本地盘 + `/img` 鉴权出图；未来切阿里 OSS **专用新桶**（如 `dangkou-catalog` + 独立 RAM AK，与 beautyclawos 四套权限域零混），改 env 即切
- 服务器：旧部署与数据清空，重新部署 v2

## 6. 自动化验收 Harness

| 场景 | 验收点 |
|---|---|
| 导入×2 | 两品类各导一次：品类询问→异步→回调→工单；审批后商品数（剃须刀~25-35 / 卷发棒~55-65）、空型号=0、图配对≥95%、无幻觉图名 |
| 重导四分类 | 改行/删行/加行再导：新增/更新/下架分别正确进审批 |
| CRUD | API 层按品类增/改/软删全通；Agent 修改走审批生效 |
| 检索质量 | 入库商品图为查询集：Top1 ≥80% / Top3 ≥95%，不达标报告并标记优化路线 |
| 报价单 | 生成 xlsx：5 列齐、图嵌入、可被 openpyxl 读回 |
| 全程微信 | 次晨用户亲手跑：发文件→答品类→收回调→批工单→发图找货→发报价单→收 Excel |
