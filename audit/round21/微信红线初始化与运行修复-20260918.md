# 微信红线初始化与运行修复（2026-09-18）

## 最终口径

- 微信档口管理入口启用时，业务转人工红线为空。
- 价格、数量、物流、定制、账期和售后示例只用于引导商家填写，不自动启用。
- 商家通过微信 Bot 提交红线并审批后，客户 TG Bot 才按原文限定条件判断是否转人工。
- 客户主动回复“找老板”仍直接获得店铺已登记联系方式。
- 未命中红线且资料不足时，Bot 说明现有资料不能确认，不虚构答案，也不擅自转人工。

## 发现与修复

1. 数据库和页面已经支持微信管理模式下空红线，但客户运行路径仍先执行旧的“价格或数量问题默认转人工”规则，绕过了商家规则。
2. 微信管理入口此前要等到绑定 TG Token 时才清理旧预置规则，绑定前的配置阶段仍可能暴露旧默认项。
3. 商品工具说明和照片匹配回执仍有“所有价格默认红线”“询价1即可转人工”的旧话术。

现已调整为：

- `wechat_managed` 模式跳过旧平台价格转人工规则，只匹配已审批的 `cs_redline`。
- 微信管理入口注册时立即进入 `wechat_managed` 模式并清理未经审批的旧播种规则。
- 照片匹配后的“询价1”改为查看对应商品资料；需要人工时客户可主动回复“找老板”。
- 微信商品工具说明明确“只按商家已审批红线，未设置不触发”。
- 阶梯报价仍不支持录入，但不再把所有价格问题描述成默认转人工红线。

## 验证

- 空红线：普通询价、带数量询价、物流和定制问题均不转人工，也不调用规则模型。
- 商家红线：商品级和店级规则按审批内容动态生效；照片候选选择仍保留商品上下文。
- 当前测试档口真实规则：

  - “拿200个什么价格” → `PASS`

- 线上数据库 `PRAGMA integrity_check`：`ok`。
