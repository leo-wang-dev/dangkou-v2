# 微信动态分类线上修复

日期：2026-09-18

用户把“微信验收吹风机.xlsx”发给真实微信 Bot 后，Bot 错误回复只支持剃须刀和卷发棒。根因不是文件或动态分类实现，而是测试服务器仍运行旧版微信插件和旧版 sidecar：插件强制 `catalog_import(path, category)`，实际 `19010` API 也要求 category，服务器缺少 `dynamic_catalog.py`、`dynamic_import.py` 和 `workbook_templates.py`。

处理：

- 停止隔离微信四项服务，备份代码、配置、systemd 单元和 SQLite 数据库到权限 0600 的时间戳目录。
- 同步已通过本地全量测试的 sidecar、动态分类模块、微信工具插件和微信人格覆盖层。
- 新人格明确：收到 Excel 直接调用 `catalog_import`，默认不传 category；不得追问“剃须刀还是卷发棒”，不得要求商家先开通分类。
- 重启 API、通知、客户 Bot 和微信引擎，四项服务均为 active；SQLite integrity_check=ok。
- 为避免旧对话历史继续锚定旧流程，备份后只重置当前测试微信的会话映射，保留微信登录凭据和 reply context。

真实服务器验证：

- 直接使用微信刚上传到服务器的原文件，导入状态 `ticketed`；识别分类“微信验收吹风机”，新增 4、更新 0、下架 0。
- 审批后形成 4 条动态商品，型号为 `WX-HD15`、`WX-HD15`、`WX-HD16`、空；重复型号和空型号均保留，4 张图片存在。
- 商家实时查询返回 4 条；客户目录返回 4 条公开商品，成本字段未暴露，商品图片接口返回 200。
- 真实模型新会话对同类文件调用 `catalog_import`，没有拒绝吹风机；对“微信验收吹风机有几个”调用 `catalog_stats` 并回答 4 款。
- 导入通知队列 `sent=1, attempts=0`；用于模型路由验证产生的重复待审批工单已驳回，避免重复入库。
