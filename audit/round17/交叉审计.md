# 客户闭环交叉审计

范围：round16 新增的客户咨询/采购笔记链路，以及与之相连的商家红线、本地商品查询、清单编辑和 Excel。使用需求→代码、代码→反例测试、测试→覆盖缺口三条检查线。本报告不宣称对全部历史代码进行逐行审计。

## 已复现并修复

| 严重性 | 问题和触发方式 | 修复 |
|---|---|---|
| 高 | “杯子100个，出表，能加急吗”在导出分支提前返回，漏掉商家红线 | 复合消息同时生成采购清单与执行红线判断，命中时发送联系方式 |
| 高 | 本地客户查询仅查 approved，隐藏商品的电压等资料仍被回答 | 商家回答增加 cs_visible 校验，与远程目录约束一致 |
| 高 | 已关联 C001 后把品名改为盘子，旧商品编号及商品图仍保留 | 统一在清单字段编辑路径取消旧关联；新增 catalog_photo/catalog_fields 来源元数据，清除自动补入信息并保留客户照片和改写字段 |
| 中 | 抽取服务超时，使“找老板”整条消息失败 | 采购抽取失败返回明确“未保存”提示，继续执行咨询/主动转人工 |
| 中 | 候选商品本地返回原始行，缺 specs；电压等字段未写入采购笔记 | 通过公开商品字段转换补全规格，排除价格字段 |

围绕商品来源修复又补测两个反例：从 C001 改选 C002 时必须换成新商品图/规格；重复选择 C001 不能丢失来源元数据，导致后续改名时无法清理旧规格。均已复现修复。

新增 `tests/test_cross_audit.py` 共8项入口回归，包含客户原图保留的正向保护。原有 round16 的11项新功能测试继续执行。

## 代码入口

- `catalog/merchant_policy.py`：复合导出/红线、隐藏商品拦截。
- `catalog/purchase_notes.py`：抽取异常降级、商品规格补全和关联切换。
- `catalog/shop_link.py`：来源字段迁移、统一清单编辑清理、禁止直接篡改商品关联编号。

## 范围与限制

- 迁移为新增两个带默认值的字段，无删除既有数据。本轮尚未部署服务器。
- 真实 Telegram 收发仍须独立商家客户 Bot；平台商家 Bot 不能代替。不能将本地传输替身测试视为线上 Telegram 验收。
- 自然语言采购意图由模型判断；测试不是对任意输入无误的保证，客户仍需核对回显。
