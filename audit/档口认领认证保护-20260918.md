# 档口认领认证保护

用户要求：不能凭名称、邀请码或自报手机号认领别人的档口，应核验档口归属。

现状核查：当前 shop_profile 保存 owner_wechat（微信号），没有经过独立核验的微信绑定手机号。不能将新申请人填写的手机号当作可信底册，也不能把号码匹配当作持有证明。

本次已实现并部署：
- 已有档口邀请码只提交认领申请，不再直接授予数据权限。
- 独立核验通过后，授权绑定具体 Telegram 数字用户 ID；转发链接不能继承原用户的认证。
- 管理员审核接口要求 HTTPS、服务认证、审核人、独立核验凭据参考编号，保存审批审计。
- 未通过认证不能查看原档口资料、绑定 bot、使用商品管理或启动客服；直接调用绑定接口及 runtime 也会校验。
- 已经通过旧邀请码认领的记录同样必须补认证，不豁免。已清除未认证账户的绑定/管理能力链接并阻止启用。
- 普通新建空店不会取得任何已有档口数据库权限；这一机制不等于营业资质认证。

审核路径：GET /merchant/ownership-requests；POST /merchant/ownership-requests/{id}/review。人工核验应基于档口原有登记联系方式，证据参考编号只记录已有核验记录，禁止因为申请人报对号码就批准。

手机号自动核验尚未实现：需要可信的历史手机号来源和验证码通道。目前没有这两项，采用管理员独立核验。后续流程应是档口标识与原登记手机号匹配，向该原登记手机号发送验证码，验证成功后只授权对应档口并绑定申请 TG 用户；不允许申请时覆盖底册。

测试：20项相关测试通过，覆盖邀请码转发、跨TG身份、未认证资料不泄露、审批鉴权/证据约束、存量认领不豁免，以及此前页面绑定与双商家运行。记录：round14/verification-tests.log。

线上核验：三个服务 active；无认证访问审核列表返回401；1条旧认领已进入待认证，绑定/管理链接已失效，不能启用；74件商品和6条采购记录保留。
