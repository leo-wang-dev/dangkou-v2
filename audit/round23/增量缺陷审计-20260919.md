# 档口微信端与客户 Telegram Bot 增量缺陷审计

审计日期：2026-09-19  
范围：三份产品文档、当前代码、微信 H5、客户 TG 对话、采购笔记、Excel、测试服务器运行与基础运维。  
结论：**业务闭环可以继续手工验收，当前代码已部署到测试服务器；尚不建议按正式生产标准对外开放。** 阻断正式商用的事项主要是凭据轮换、服务器续期、管理链接权限收敛和自动异地备份，不是商品查询或采购清单代码故障。

## 本轮发现并已修复

1. **客户清单泄漏内部关联字段。** 旧笔记可能把“商品编号、商品类别”带到客户页面、Excel 和模型提示词；客户链接接口还返回客户/档口关联 ID。现在客户投影、导出和模型入口均二次过滤，历史队列快照也不会继续泄漏。
2. **重复型号无法正常介绍。** 真实库中 `WX-HD15` 有红、蓝两行，旧逻辑无法唯一选中时只回复“无法确认”。现在会展示两个候选的公开规格和图片，要求客户继续按颜色/规格确认，不猜商品，也不展示价格。
3. **出表使用旧商品快照。** 客户记笔记后，如果商家在出表前补录或修改商品，旧实现不会重新读取。现在“出表”前重新查询真实档口库：唯一匹配会补全最新规格和商品图，档口不存在的商品仍作为普通笔记导出；客户自己修改过的字段优先保留。
4. **管理页地址栏清理令牌后刷新失效。** 现在首次加载即移除查询参数，并按管理路径在当前标签页会话中保存，刷新仍可继续操作。

主要实现位置：

- `catalog/shop_link.py`：客户安全字段投影。
- `catalog/cs_export.py`：Excel 渲染前再次过滤内部字段。
- `catalog/api.py`：客户链接响应不再返回内部客户/档口 ID。
- `catalog/purchase_notes.py`：出表前重新读取商品库并保护客户编辑。
- `catalog/csbot.py`、`catalog/merchant_policy.py`：重复型号多规格介绍。
- `static/index.html`：管理令牌离开地址栏后仍支持刷新。

## 正式商用前仍存在的缺陷

### P0：上线前必须处理

1. **已经公开过的凭据必须轮换。** Telegram Bot Token、百炼 API Key 和服务器密码曾出现在对话或截图中。仅从代码里隐藏不能让旧凭据失效，必须分别在 BotFather、阿里云控制台和服务器侧更换。
2. **服务器即将到期。** 现有服务器资料标明 2026-09-25 到期，距本次审计只有约 6 天。应先续费或迁移，再承诺正式运行。
3. **商家管理链接权限过大。** 目前链接首次打开仍携带长期服务令牌；页面已经会立即从地址栏清除，但转发原始链接仍等于转交完整管理权限。正式方案应改为短时、可撤销、限定档口和操作范围的 H5 会话令牌。
4. **没有业务数据自动异地备份。** 服务器只有人工同盘备份，没有档口数据库、商品图、客户图片和运行状态的定时异地备份与恢复演练。磁盘或实例损坏时，同盘备份无法救援。

### P1：建议正式开放前处理

1. **SSH 与端口防护较弱。** SSH 允许密码和 root 登录，UFW 未启用；旧 `dangkou2` 的 8890 端口绑定全部网卡。旧服务按既有约束没有改动，但应由服务器负责人确认调用方后收紧安全组/防火墙和 SSH 策略。
2. **老板 TG Username 仍为空。** 当前“找老板”可返回微信，不能同时返回老板 TG。代码已支持两种联系方式，测试档口还缺这项商家资料。
3. **缺少外部监控和告警。** 当前有 systemd 自恢复和发件重试，但没有独立的健康探测、队列积压告警、磁盘告警和通知渠道。
4. **没有真实并发容量结论。** 功能和回归测试覆盖完整，但尚未做多商家、多客户同时发图、识图、出表的压力测试。
5. **旧产品文档仍有冲突。** 阶梯报价、默认红线、平台 TG Bot 管商家等内容已被后续决定替代，应更新正式 PRD 和验收清单，避免运营和测试按旧口径验收。

### P2：后续维护项

1. 动态分类的“商家正式报价单”仍没有通用字段映射。客户采购笔记 Excel 已正常工作；如果将来要出对外正式报价，需要商家明确每个分类的价格列和模板。
2. 库存、现货、交期、物流等只能回答商家已维护的数据；缺字段时系统会明确说“尚未填写”。如果运营要求回答这些问题，应要求商家在分类表头或档口资料中补齐，而不是让模型推断。
3. 两条依赖弃用 warning 应在后续依赖升级时消除。

## 当前可以确认的业务边界

“商家微信维护商品/分类/红线/TG Token → 审批 → 客户进入商家自己的 TG Bot → 查询商品规格和图片 → 发文字或照片记采购笔记 → 档口商品实时补全 → 未命中商品照常保留 → 导出混合 Excel → 命中商家红线时给联系方式”已经贯通。

因此，当前版本适合继续真实商家手测和受控试运行。完成 P0 四项并复核 P1 的外网安全与监控后，才适合认定为正式生产可用。
