# 档口身份与两端关联：本地实现和验收

范围：仅修改本地代码、隔离测试库和文档。未连接或修改生产服务器，未部署，未更换正在运行的 TG 测试服务配置，也未把测试档口名填进用户实际清单。

## 改动
- 一个档口一个数据库：稳定 shop_id 关联商品，迁移保留历史内容并幂等；新商品自动获得本库 shop_id，阻止写入其他档口 ID。
- 商家插件/API 支持档口名称、档口号、联系人及 TG bot ID/Username，与原老板微信/TG、地址资料共用审批；审批时再次验证，防止并行旧工单覆盖较新资料。
- bot 启动调用真实传输的 getMe 接口核对身份，未绑定或 Token 属于其他 bot 时在处理消息/发送队列前退出。测试使用接口替身，不调用真实 TG。
- 新照片分开记录接待档口、来源档口及依据。默认带出接待档口资料但明确供货关系待确认；照片明确为外部来源不覆盖；客户可指定“本店”或外部来源；历史未知归属不自动回填。
- 关联本店的页面/新 Excel 使用最新已审批资料；修改为外部来源解除 ID 并清除本店联系方式；发件箱保存出表时快照。
- 新增鉴权只读 /shop/linkage 与 scripts/check_shop_linkage.py，检查 B 端 API 与 C 端所用数据库的身份是否相同。

## 验证内容
- 新增 tests/test_shop_linkage.py：审批前后生效、稳定身份、商品归属、客户照片记录、网页/Excel、店铺资料更新、外部来源切换、bot ID 不匹配在收发前拒绝、并行审批冲突、旧 schema 迁移幂等、跨数据库身份检查。
- 新增 tests/e2e/test_shop_linkage_page.py：真实启动隔离 API、浏览器点击批准档口资料和商品阶梯价；C bot 在同库取到新阶梯价；客户页显示档口资料；网页修改外部来源并自动清空本店联系方式；刷新、点击下载 Excel、检查图片、手机宽度显示。
- 真实浏览器/API/SQLite/Excel 使用实际实现，外部微信引擎、TG/LLM 使用替身。本轮不代表生产微信/TG已经联通。
- 旧库迁移测试使用与旧库结构相符的本地 fixture，并未下载/修改生产数据库。
- 全量回归：333 passed、3 skipped、0 failed。3项跳过的是未开启的外部真实服务测试。结果见 round8/verified-tests.log，浏览器截图和 trace 见 round8/browser/。node tests/test_plugin_syntax.mjs 的10个工具注册与参数传递通过；编译和 diff 检查通过。
