# 商家 Bot 接入实现与验收（2026-09-18）

## 结果

完成本地实现和测试，未部署、未切换线上 @kehu_serve_bot。现有平台 bot 作为商家接入助手；商家创建自己的独立客服 bot，由服务端隔离运行。用户无需通过旧微信档口助手开通。

## 已实现

- 对话开通、草稿、跳过/保留、清空、回退、暂停/继续、显式确认，TG/微信联系信息校验。
- 私聊 Telegram 身份校验；新建空档口；已有档口一次性管理员邀请码认领。
- 商家红线可选，空值不默认生效，确认前不影响生效版本。真实模型测试验证“月结超过30天”与“15天”的区别及规则删除后的行为。
- 商家报价规则原文保存和展示；不自动生成数量对应的阶梯报价。
- HTTPS 一次性 Token 表单，验证身份后二次确认，拒绝平台 bot、重复绑定、已有 webhook、过期/重复使用链接及运行中更换绑定。
- Token 不入 SQLite/聊天历史；仅写权限 0600 的独立凭据文件。错误响应不返回提交的 Token。
- 商家 bot 与该档口 API 共用数据库，不同商家分库；进程启动/暂停/恢复、限额、异常重试。API 校验完成后才标记 running。
- 独立商家清单公开代理，仅允许清单页面及带随机 Token 的清单操作；不暴露管理接口。
- 旧 bot 更换的显式离线迁移工具：文件锁、队列排空检查、备份、旧队列归档；保留档口 ID、商品、客户采购清单。
- 两个 systemd 服务模板和配置/部署说明。

## 测试结果

1. 全量 `pytest -q`：**399 passed, 1 skipped**，约 124 秒。记录 `audit/round12/tests.log`。
2. 最后运行状态竞争保护修改后，相关回归：**15 passed**。记录 `audit/round12/onboarding-tests.log`。
3. Playwright 实际点击绑定页：填写 → 验证身份 → 核对用户名 → 确认 → 成功；无前端脚本错误。
4. 真实 supervisor、两套 API/bot 子进程：同时运行、单店暂停、恢复、网关按店隔离及跨店 Token 拒绝。Telegram 传输是本地可控替身，不冒充真实商家 bot 验收。
5. 全量测试含真实百炼模型、用户四张原始照片识别与 Excel 图片验证，以及新商家自定义条件判断。
6. 插件 10 项注册/调用约束检查、Python 编译、JS 语法、`git diff --check`、`pip check` 通过。

首次全量发现旧机器人将“卖什么品类”交由模型误判转人工；已改为直接读取商品目录，加回归测试后全量通过。两个剩余 warning 为第三方测试依赖弃用提示。

唯一跳过项：真实 Telegram 发信/轮询测试没有开启 `RUN_REAL_TG=1`。本次没有借现有线上 bot 自动给用户发送测试消息，也没有启动第二个线上轮询消费者。
