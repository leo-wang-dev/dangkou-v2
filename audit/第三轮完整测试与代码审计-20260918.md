## 3. 本轮发现并修复的代码问题

先写失败用例再修复：首批 16 个后端探针全部复现失败；随后补充报价边界和并发测试，最终 24 个后端回归通过。两项新增浏览器用例也都有修复前失败记录。

| 问题及后果 | 修复与验证位置 |
|---|---|
| “这款能月结吗”没有数量时丢失上一商品的红线；换问另一种货却沿用上个商品价格 | `catalog/csbot.py` 收紧会话商品继承，保留明确指代；回归覆盖两种相反情况 |
| 未知货物没有按要求转商家；已知但不可观测商品的处理不完整 | `csbot.py` 补充转人工及已配置联系方式输出；保留普通“有什么货”问答分支 |
| 较大金额输出被有效数字格式舍入，例如 12345.67 显示错误 | `catalog/cs.py` 用 Decimal 解析并按十进制格式输出；实际金额断言通过 |
| 模型判定期间商品被关闭或价格/规则变化，仍可能回旧报价 | 回复前重新核验商品状态、阶梯价、成本和有效红线，变化则转人工 |
| TG 轮询失败会阻止发送已经排队的通知 | `scripts/run_cs_bot.py` 先处理待发队列再轮询；模拟轮询失败验证通知仍被尝试发送 |
| 最前面 100 条失败消息能挡住其他客户 | 去掉处理前的固定截断并按客户顺序处理；回归验证后续另一客户不被饿死。当前方案仍需容量治理，见后文 |
| 图片处理失败后，审批票已消耗或商品其他字段已经部分落库 | 图片校验/落库并入审批事务，移除中途提交；异常回滚后票仍可处理，商品字段不被半更新 |
| 调换两张图片顺序时复用文件名，导致图片内容互相覆盖 | `catalog/api.py` 使用独立文件名并限制图片来源；交换顺序后两图均保留 |
| 客户清单错误请求体、缺文件上传导致 500 | 返回明确的客户端错误；回归覆盖 |
| 检索先截 TopK 再过滤下架项，导致明明有有效商品却返回空结果 | `catalog/search.py` 先过滤失效项、去重再截取 |
| 查询某品类的统计，total 混入其他品类 | `catalog/api.py` 统一统计范围并校验品类 |
| 导入通知将含服务密钥的完整链接持久化到消息队列，违反文档要求 | `catalog/notify.py` 保存 doc_id/stats，发送时从环境配置拼装通知；测试核验队列不含服务密钥。历史队列若曾存密钥，本次代码不会自动清洗 |
| 报价入口允许异常数量、无穷金额或不合法折扣/定金；下架商品可能参与报价 | `catalog/quote.py`、API 增加数值和商品有效性校验，在加载模板前拒绝无效请求 |
| 慢模型请求占用全局数据库请求锁，其他正常请求被一起拖住 | 文件数据库改为请求独立连接；内存测试库保留串行保护。用事件控制慢请求验证另一请求可完成，这不等于负载测试 |
| 导入编辑既有商品时清掉阶梯价/可观测字段；待审批新图无法预览 | `static/index.html` 和 API 保留原有 CS 配置并展示本次导入图片；两项真实浏览器回归通过 |

附带修正：清单显示数字 0、预检加入解析 CLI 是否存在、旧 B 端 Harness 的过时报价入参/列数检查/按型号去重预期/错取最新工单/重导来源标识，以及检索评测失败退出码。真实 B 端 Harness 仍缺数据，只验证了预检阻塞和脚本语法，未声称其全部真实场景已通过。

## 4. 仍未关闭的功能与代码风险

下表区分“代码未实现”“源码可见风险”和“缺真实验证”。不把尚未复现的风险写成已发生的故障。

| 优先级 | 未关闭事项 | 当前事实与所需工作 |
|---|---|---|
| 上线阻断 | 正式模板及真实报价验收 | 8 个测试失败。必须取得原商家模板，完成金额、整箱数量、图片、版式和推送文件验收 |
| 上线阻断 | 真实 TG、微信、模型、解析 Agent、目标引擎联调 | 插件和 API 存在不代表微信已接好；缺凭证/原图/目标引擎配置，需独立测试号贯穿导入→审批→询价→转人工→老板收到通知 |
| 上线阻断 | 外部 Excel 解析执行权限 | `catalog/agent.py` 使用 `claude --dangerously-skip-permissions`，解析进程继承服务用户权限。静态确认，无恶意文件攻击验证；处理不可信供应商文件前应隔离执行用户/容器、限定输入输出和可用凭证 |
| 功能缺口 | **纯照片匹配店内商品后报价** | C 端照片目前走采购清单抽取。处理 caption 不等于实现纯图询价；人工清单 E1 的照片分支未完成 |
| 功能缺口 | **店铺信息和正常店铺问答** | `shop_profile` 只有老板 TG Username、微信两个字段，工具支持读取/修改后审批。地址、营业时间、发货/物流、FAQ 等未形成可维护并可检索的资料；“你们在哪条街”不会得到已核实的店址。目标引擎是否另有知识库未验证 |
| 功能缺口 | **只换图片的 Excel 重导** | `catalog/classify.py::_differs` 只比较模板字段，图片列表不参与差异判定；文字不变仅换图可能不产生更新。源码可见，尚未补真实 Excel 回归与修复；需基于图片内容识别变化，避免临时文件名造成误更新 |
| 高风险待验证 | 同一来源多个待审导入的并发/过期快照 | 分类基于导入时已批准商品；批准另一个工单后，旧待审工单没有完整版本冲突机制。存在重复新增或覆盖较新数据的风险；未做真实并发导入复现，需补冲突检测与跨工单测试 |
| 高风险待验证 | 自然语言红线准确率及抵抗诱导 | 代码约束输出格式、错误时转人工，但不能证明模型总能识别底价、违禁或隐含投诉。需真实商家话术、边界问法、改写和诱导样本的黄金集，尤其验证商品规则覆盖和系统规则优先级 |
| 运行缺口 | 通知和消息处理能力 | 已持久化重试，但 B 端通知依赖 C bot 进程消费；bot 未启动/缺 token 时通知无独立发送 worker。仍串行、缺限流/有界分页/重试退避/死信处置及容量测试 |
| 运行缺口 | 检索索引恢复及质量 | 嵌入失败后未见完整的持久化自动补偿队列。真实 Top1/Top3、同款不同图及近似型号误命中尚未验证；“用已入库主图搜自己”也不足以证明实拍找货能力 |
| 运行缺口 | 正式部署、升级回滚和告警 | 部署脚本仍非原子版本切换；外置目录不在默认 data 备份范围。没有实际服务器升级、原生产库迁移/恢复演练；`/ready` 主要检查配置/本地状态，不能代替模型/TG/微信连通和 worker 心跳监控 |
| 运行缺口 | 图片/清单保留与清理 | 事务失败可能遗留未引用的图片副本；原图、导出、过期链接对应文件的保留/删除策略及定期清理未形成闭环 |
| 待产品确认 | 转人工后的话题沉默/冷却 | 三份文档明确语义未定；沿用逐条判定，没有擅自加整会话冷却 |

“老板联系方式”目前流程符合这次对话的要求：商家对 B 端说 TG 和微信 → 创建审批工单 → 老板批准 → 写入 `shop_profile` → C bot 转人工时发送 TG Username/链接与微信号 → 客户自行联系老板。**不需要实现老板加入原 bot 会话。** 真实微信对话能否调用到工具仍待部署接线验证。

## 6. 文档本身的纰漏及需要改写之处

1. **测试步骤互相污染。** C2 把规则改为 50 个/成本 1.5 倍，E2 却期待 30 个直接报价；C5 又用商品规则替代店规，E4/E5 继续期待店规生效。应给每个场景独立初始化规则和商品，或明确还原步骤。不要用一条连续聊天去证明互相矛盾的预期。
2. **红线覆盖必须说清楚。** 商品规则整条替代店规，因此只写“低于 9 块不谈”并不自动保留店规的账期、投诉等条款；系统级规则仍保留。测试应分开验证继承、替代、系统优先级。
3. **转人工话术更新。** “商家马上来”会让用户误以为老板在原会话接管，应改为“可通过以下 TG 或微信联系老板”，与用户本次已定方案一致。
4. **店铺资料不可混同联系方式。** 当前只落了 TG/微信，文档没有交代地址、时间、物流和 FAQ 的维护入口、审批和来源；不能据此承诺店铺问答完整。
5. **历史全绿是旧环境结论。** Handoff 中的 135 单测、常驻 bot、真实 TG 已验证及 `/Users/elias/...` 路径，不能视为当前机器和修复工作区的证据。
6. **H2 操作入口写错。** 统计/搜图/报价在插件工具/API，不在现有 H5 按钮中。选择通过微信对话验收，或另立页面功能需求，不能让测试人员寻找不存在的按钮。
7. **H3 和健康检查需要三态。** 实际 Harness 的分组与文档不一致；缺依赖应写 BLOCKED 而不是绿色通过。`/health` 正常不能推出 bot、模型、通知可用。
8. **两天失效完全可以自动测试。** 控制测试数据库到期时间即可；原文“不好当场测”不应成为略过安全边界的理由。客户链接是可转发的持有者凭证，不是只限某个浏览器访问。
9. **“部署后自动接上”缺验证步骤。** 需要明确目标引擎版本、插件注册、工具可见性、微信登录、通知路由和真实消息回执，当前只有插件契约通过。
10. **数据和秘密约定应落到真实实现。** 主运行库为 SQLite，`kb-library/` 的原文字样不足以说明生产数据归属；导入来源、备份范围及历史数据迁移要写清。服务密钥曾进入通知队列，本轮已阻止新增，已有部署需检查历史数据并按需轮换凭证。
11. **报价单与采购清单不可混用验收结果。** 前者依赖商家 14 列模板，后者是动态字段 Excel；后者导出成功并不关闭那 8 个失败。
12. **缺附件导致基线不完整。** 应把 v1.2、真实照片及黄金答案、报价模板、厂家源表纳入受控验收材料；凭证通过环境配置交付，不写进报告或仓库。
